# What is this ?

kmath is my own opinionated c++20 templated math library. As of right now, it shouldn't be used in any production project as the APIs and structures should be considered unstable: I will change and move things around depending on my projects needs and on how I want to interact with a math library. This project exists only for me to learn how to a math library is implemented and to be able to play with representations that are not necessarely common in already existing math libraries.

Here is what's present in this library:
- `base.hpp`: implementation of basic math function (such as trig functions and others) that can be used with vectors and matrices. The implementation of most functions is based on c++'s standards library.
- `concepts.hpp`: concepts that are used to categorize different objects.
- `vector.hpp`: vector math implementation (Vec2, Vec3, and Vec4).
- `matrix.hpp`: matrix math implementation (Mat2, Mat4, and Mat4).
- `color/`: implementation of color space standard conversion functions (including Lab LChab XYZ, xy, HLS, HSV, HWB, OKLab, OKHSL/HLV/HWB), and functions related to colors.
- `angles.hpp`: helper functions conversion to spherical and euler coordinates. Angle lerp and differences.
- `euclidian_flat_3d.hpp`, `motor_3d.hpp`, `rotor3d.hpp`: an implementation of 3DPGA ($\mathbb{R}_{3, 0, 1}$) for computer graphics.
- `pga_3d.hpp`: implementation of 3DPGA multivectors (this code was partially generated by a PGA generator by enki).
- `interpolation_functions.hpp`: implementation of common interpolation functions.
- `print.hpp`: what to pull to print the different structures.

If anyone besides me is interested by my todo-list for this project here are some things that are planned (in no particular order):
- A refactor of the printing header to not pull the whole library (yeah, that's pretty bad for compile time).
- Add a project benchmark and optimize functions all over the codebase.
- Write AVX SIMD optimized version of some functions in the codebase (would be interesting for PGA functions).
- Rewrite the color API to be used in GLSL shaders.
- Try to complete the unit test battery to cover most of the project (this is a long one).
- Have a 2DPGA implementation ($\mathbb{R}_{2, 0, 1}$).
- Implement 1st, 2nd, and maybe higher order dynamic (frame-rate resilient) interpolators (eg. spring interpolators for dynamic systems).
- Refactor the `pga_3d.hpp` header to be more consistent with the rest of the library.
